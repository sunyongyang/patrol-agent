## 维护契约

写代码的人（包括 AI）在以下情况**必须同步更新文档**，不要留到"以后再补"：

| 你改了什么 | 必须更新 |
|---|---|
| 新增/删除意图、改工具签名 | Spec §6.2 + 交互设计 §3 |
| 改数据模型（加字段/改语义） | Spec §8 + **附录 A.3** |
| 改检测能力边界（换模型、加算法） | Spec §5.3/§5.4 + **附录 A.5** + README 的能力边界表 |
| 改指标口径 | Spec §6.5 + **附录 A.4** |
| 实现了一个 A.7 里标"尚未实现"的东西 | 把该项从 A.7 移除，并在 §13/附录里记录 |
| 踩了新的坑并修复 | **附录 A.6**（这一节对后来者价值最高） |
| 改了配置文件的字段 | 对应 yaml 的注释 + Spec 相关章节 |

### 与 Obsidian vault 的关系

用户的 Obsidian vault 里有一份工作副本：

```
D:\ObsidianVaults\obsdianPW\91_实验项目\agent_patrol\
```

- **实现相关的事实只在仓库维护**（附录 A、README 的能力边界表）
- 设计意图两边都有，手动保持同步；**以仓库版本为准**
- vault 里的 `[[wikilink]]` 语法在 GitHub 上会退化成普通文字，这是预期的，不要为了 GitHub 好看而改成普通链接（会破坏 Obsidian 里的跳转）
